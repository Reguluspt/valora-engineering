## 3. Commercial semantics and exact basis reference

Exactly three axes are allowed: `vat_included`, `transport_included`, `installation_labor_included`. Each recorded actual value is a strict boolean. For an intact KNOWN Project basis, an A13-eligible quote is presumed to follow the requested inclusions unless a recorded applicable actual value differs. This is PO-authorized presumption, not evidence that a Supplier attested compliance. No affirmative row, checkbox, upload, OCR/AI inference, confirmation step or mandatory acknowledgement is created for ordinary quotations.

Consume the complete typed A18 reference from the caller's coherent snapshot: `contract_version`, `organization_id`, `project_id`, `state`, `reason_code`, `policy_version`, `revision_id`, `revision_number`, `head_version`, `content_sha256`, `declarations`, `authority_fingerprint`, `project_row_version`, `case_version`. The version is exactly `project-commercial-basis-reference-v1`; KNOWN policy is `project-commercial-basis-v1`. Never independently reconstruct the reference from Project fields or a second SQL algorithm.

| A18 state | Deviation write / ranking disposition |
| --- | --- |
| KNOWN | Initial Record requires at least one affected axis actually different from the exact referenced declarations. Pin revision ID/number/head version/content digest/policy and fingerprint at observation. |
| UNKNOWN | Only genuine legacy absence: no head/revisions/receipts; null/0/0/null authority tuple, null declarations and `legacy-absent-v1` fingerprint marker. No new Record/Correct/Clear; return `commercial_basis_required`, next step explicit A18 declaration if DRAFT and authorized. Ranking UNRANKABLE, never infer false. |
| UNAVAILABLE | Corrupt, contradictory, unsupported or unprovable basis; no usable tuple or new professional metadata write. Return `commercial_basis_unavailable` and bounded diagnostic/reload direction; do not suggest overwriting corrupt history. Ranking unavailable/UNRANKABLE, not compliant. |

A retained observation always keeps its historical basis tuple, even after the current basis changes. Against a new KNOWN basis, compare recorded actual values with new declarations; a previously differing value can now match. Unrecorded axes use the current PO presumption. Historical negative knowledge is retained, including when it currently matches. Only explicit correction or targeted clear changes that knowledge. Basis change itself invalidates all relevant selection heads under A18; later equality never revives them.

Initial Record names only differing axes. Correct may replace a previously recorded actual with a matching value: that is correction of known history, not mandatory affirmative attestation. Clear explicitly closes targeted known assertions and resumes presumption for those cells, with a protected reason; it does not certify Supplier compliance. No blanket clear of unknown/unrecorded cells. Metadata writes cannot fix A13 eligibility, source loss or upstream holds.

## 4. Quotation identity and continuity model

Use one deviation journal/head per `(organization_id, project_id, quote_id)`, where `quote_id` is the native logical DocumentRecord. Within it, a knowledge cell is `(sealed line_id, axis)` with one live assertion or an explicit cleared state. Its immutable origin records exact quote revision fact ID/number, contributing confirmation fact ID/receipt/audit, effective item ID **and owner `fact_id`**, seal/membership and line binding, source DocumentRevision/binding/generation/digest, Supplier identity and the A18 observation tuple. Arrays labeled “all items” must be expanded into a frozen, nonempty list of exact effective items/lines; never store an open-ended wildcard.

Record/Correct/Clear target the currently contributing confirmed revision and exact effective items in its `confirmed_items`, not `heads` merely because it is newer. A metadata action therefore operates on an already professionally confirmed quotation; it adds no confirmation of its own. No new observations on unconfirmed drafts in this v1 proposal. Pending draft lineage carries prior knowledge and can be displayed, but draft remains ineligible. A newly discovered draft difference may be recorded on its exact contribution after the existing A13 confirmation, without automatically confirming it or blocking ordinary confirmation on a new attestation. A rejected/withdrawn quote's history remains readable; no active contribution means no new metadata command target.

Knowledge survives temporary noncontribution. The journal retains dormant cells for omitted or withdrawn lines. Within the same native logical quote ancestry, exact same sealed line identity is the only automatic correspondence; repeated source locators, names, prices, catalogue IDs, Supplier names/merge targets or list position never establish a mapping. Distinct item IDs/owner facts are recorded on both ends. A line not present has no candidate; if it reappears later in that same lineage, its unresolved actual values return with their original provenance. This is conservative retention of recorded knowledge, not a claim that new source text was inspected.

### Adapter and immutable lineage records

Future `ResolveSupplierQuoteDeviationApplicability` is a pure resolver over the intact native A13 fold, the full deviation chain and the A18 reference. The future A13 command adapter also appends a `lineage` journal fact whenever an A13 mutation changes applicability for a quote with recorded history. It references the originating A13 fact/receipt and explicit previous deviation head; stores the before/after bindings for all retained cells; copies no invented actual values. Registration of an ordinary quote without history creates no deviation journal. Existing human A13 command admission authorizes only this mechanical continuity side effect, not a new human commercial observation or system confirmation.

Lineage fact actor/session/time comes from that real A13 command; its auxiliary receipt links the native A13 receipt and uses a separate namespace. The parent transaction owns commit and its single Project increment. A parent command replay returns its original outcome without creating another lineage record. Missing, duplicate or inconsistent required adapter output fails closed. No live head update is allowed without an immutable fact and exact receipt/audit correspondence.

Metadata commands themselves re-resolve both latest draft and contributing confirmed branches. A deviation discovered on the contributor **after** a negotiation draft was created must immediately appear in that draft's inherited applicability; it cannot depend on an old draft-creation snapshot. Store both projections in the new metadata fact's protected applicability snapshot. Pure reads recompute and verify from origins/native ancestry, not just a stale materialized binding. A18 basis changes affect comparison through its own fingerprint without rewriting the deviation journal.

| Native event | Required deviation behavior |
| --- | --- |
| Latest negotiation draft, unchanged contributing revision | Contributor keeps exact item/confirmation authority. Draft gets pending same-line lineage; no selected-head invalidation merely for latest draft movement. Shared invocation CAS refreshes. |
| Draft line-registration replacing an effective item | Append lineage binding from previous draft owner to exact new item/owner for that line. Preserve assertions. Confirmation later verifies the final effective item set, not the first registration. |
| Correction or replacement | Preserve knowledge on same logical quote/line; old contribution is withdrawn by native A13. New draft is not eligible until ordinary human confirmation. Supplier correction does not erase knowledge. |
| Successor confirmation | Bind retained cells to its exact confirmation and item owners. Superseded/omitted old items never remain candidates; no fallback. Selected predecessor loses native eligibility independently of commercial comparison. |
| Omission, rejection or withdrawal | Retain dormant cells and their last exact bindings. Optional draft rejection does not clear an intact confirmed predecessor's knowledge. A later same-line return cannot silently reset it. |
| Supplier merge/deactivation/identity ambiguity, expiry, source change/loss | Retain history; native A13 eligibility and global concerns prevail. Never follow merge target, refresh deadline or substitute source automatically. Source replacement within the logical quote uses native explicit revision lineage. |
| Broken ancestry, changed seal/line identity, duplicate or contradictory cell provenance | Affected applicability UNRESOLVED; no automatic suggestion for that line. Journal corruption is global UNAVAILABLE, not an empty negative set. No guessed mapping or clear-as-repair. |

Native A13 replacement is a revision of the **same** logical quote. A new DocumentRecord has no native cross-quote predecessor and is a separate quotation, not an automatically mapped successor. This contract adds no cross-quote replacement command. If a requested replacement requires transferring unresolved knowledge to another logical quote or a different sealed line, stop and return the exact mapping exception to Gate Owner; the purported replacement cannot be presented as automatically rankable. Genuine independent quotations retain E1-B presumption. No identity heuristic creates or clears a cross-quote relationship.

AuditEvent currently has no suitable composite authority key; audit ID FK alone is insufficient. Application roles cannot disable these guards. Scope and append-only SQL-negative tests are mandatory; DDL is supplied only by a future authorized migration. Avoid modifying any historical row while adding redundant keys or guards.

### Canonical content and digest boundaries

Use version `supplier-quote-commercial-deviation-v1`: canonical UTF-8 JSON, sorted keys, compact separators, no NaN/floats, lowercase hyphenated UUIDs, exact integer generations, strict booleans, UTC with six fractional digits and `Z`. Sort cell snapshots by canonical line UUID then axis; reject duplicate request cells rather than silently deduplicate. Normalize bounded plain text once at validation, then store/hash exactly that validated value.

- `content_sha256`: version, full fact scalar/provenance/parent/receipt/audit identities, full ordered cell snapshot and typed applicability snapshot. Exclude itself, receipt result digest and shared CAS to avoid cycles.
- `request_sha256`: authenticated org/actor/Project/quote, command kind/version and every normalized input including UUID, session, all expected identities/tokens, exact target cells and protected reason. Lineage requests are server-built from exact native parent receipt/fact and prior deviation head, not new client data.
- `result_sha256`: immutable command/receipt/fact/generation/content/pre-post Project identities, audit IDs and integrated A20 observation references. Fresh shared Case State is separate from this digest because it includes receipt proof.
- `authority_fingerprint`: journal version/scope, exact terminal fact/generation/digest or scoped `deviation-absent-v1`, integrity state and verified applicability projection. Current A18 fingerprint is a separate shared contributor and part of the consumer comparison result, never a recursive dependency on `case_version`.

Digests are integrity checks, not authorization or encryption. A matching hash cannot waive a mismatched scalar FK, incomplete source/confirmation proof or missing receipt/audit.

The versioned `applicability_snapshot` contains native latest revision ID/head version, contributing revision/confirmation IDs (nullable only when there is no contributor), A18 observation reference for professional commands, and one ordered entry per retained cell. Each entry names its stable origin/assertion, original exact tuple, and before/after projections for contributor and latest draft: RESOLVED with exact revision/item/owner/line/seal/source identities, DORMANT with explicit absence reason and last binding, or UNRESOLVED with bounded reason and retained candidate identities. It also retains the ordered native predecessor fact IDs that prove each mapping. No public raw source target is included. Recomputing a historical fact uses its pinned native journal cutoff/parent fact or metadata pre-write Project version, not today's quote head; current read independently folds all later events. Metadata with no prior cell uses an explicit absent entry. A lineage fact with no resolved contributor remains valid historical continuity, never positive eligibility.

### Transaction, final check and replay order

1. Strict validation and active authentication; acquire scoped Project `FOR UPDATE` first. Reload after waits. Lock/admit actor/org/grants and owned session, then canonical upstream/seal/lines/reference/Supplier/Currency/document dependencies in existing order. No write or external notification yet.
2. Secure receipt arbitration by UUID after admission. Mutation replay requires exact original actor/tenant/Project/quote and still-active original owned session plus current edit permission. An intact identical request replays before DRAFT/stale-CAS/changed-head/no-op checks, with no new effects. Any changed invocation field is bounded 409 reuse conflict; never disclose another scope's receipt.
3. For a new invocation validate DRAFT, Project/shared CAS, A18 tuple, deviation head/generation and all native latest/contributing/item/source/line identities. Resolve the entire quote's retained cells and Project-global A13 integrity, not only submitted rows. Reject definite mismatch before appending anything.
4. Lock deviation head (absence serialized by Project), then future exact selection heads/generations in sealed-line order. Allocate IDs and append fact/full cells/head/receipt/minimized audit. Set Project `updated_by` and increment Project version exactly once. For an A13 `lineage` adapter the parent already owns that one increment; it must not increment again.
5. If official selection is activated, call A20's sole writer for proven affected selected targets in this same transaction (§9); capture observation references in the enclosing receipt. Resolve expected **post-write** shared state, including own fact/receipt/audit/version/observations. Revalidate admission, session, DRAFT, basis/native source/expiry and all scope/currentness at the outer-commit boundary against post-state, not old input CAS.
6. One outer commit publishes everything. No nested independent commit, durable receipt reservation, partial target success or commit-then-enqueue invalidation. Validation, audit, A20, deferred-constraint or final-check failure rolls back every effect and the Project increment.

Use named UUID uniqueness constraint `uq_sqcd_receipt_command`. After a concurrent uniqueness failure, roll back the attempt and use a fresh transaction for secure original-UUID receipt lookup; identical committed invocation may replay, different payload conflicts. Other integrity failures are not success. Project serialization plus exact CAS gives one winner even for disjoint lines/axes. Snapshot isolation/serialization failures require fresh transaction handling; no silent automatic professional rebase or new UUID.

First success 201, identical replay 200: `{result, replayed, historical: true, current_context}`. Immutable `result` includes scoped IDs, contract, command/receipt/fact, predecessor, generation/content, changed cell identities, pre/post Project versions, audit and observation references, UTC. `current_context` is a separately resolved nullable current Project/shared token and availability/reason; never relabel a historical receipt as currently effective. ## 7. Read contracts, security and recovery
