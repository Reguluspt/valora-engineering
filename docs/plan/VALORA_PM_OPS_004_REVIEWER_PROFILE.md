## Freeze, privacy and independent dispatch

Use the certified [packet contract v2.0](VALORA_PM_OPS_004_REVIEW_PACKET_CONTRACT.md). Review the selected public/synthetic source inventory and binding authority spans; pin its exact file digest. Freeze one clean commit. Build/verify a complete immutable packet containing all changed candidate text files (deleted files at BASE) and all required authority spans. Record BASE, HEAD, packet SHA256/bytes, normalized manifest inventory SHA256, changed-file blob/SHA256/line identities and C1/C2 spans. Packet bytes are not tokens. The packet does not replace any separately required before/after patch assessment.

Two separate native sessions receive byte-identical packet/manifest and the same task/context/evidence. Native reports, sessions and transport receipts are kept outside the source worktree and out of one another's inputs. Reviewer A and B must not access the other's report before both are final. Record model/terminal provenance and pseudonymous session SHA256, source selection and isolation evidence. Self-asserted independence is not proof; the lead checks dispatch, directories and actual permitted tool activity. A fresh session per reviewer is required; never resume an implementer's session.

Only reviewed source and sanitized final reports/metadata may be retained or published. Never include credentials, customer/appraisal data, raw transcripts, raw prompts, private reasoning, provider debug logs or secret-bearing tool arguments. Do not use an optimizer as a log sanitizer. Reviewers are read-only, with no credentials, external mutations, source edits, paid follow-up work or unrelated scope. Permission controls must restrict access to the assigned public packet; OpenCode supports [runtime inline config](https://opencode.ai/docs/config/#precedence-order) and [tool permissions](https://opencode.ai/docs/permissions/) for read-only invocation. These are invocation restrictions, not provider budget controls. Native CLI bookkeeping is distinct from source modification; do not publish its raw session storage.

For Antigravity, a read-permission blockade may use the existing CODEX §10.1 read-gate exception only with the same strict read-only prompt and isolated source input. It does not authorize writes, terminal mutation, plan auto-approval or resource access. Missing source access is INCOMPLETE, never clean PASS. Tool failure/unknown terminal requires STOP and Gate Owner retry disposition.

## Substantive final report contract

The native reviewer produces a complete human-readable final report, not only a success header or receipt. All seven sections below are mandatory, including a clean no-finding outcome. Keep decision-relevant evidence complete; do not impose a word/token cap that discards material P0/P1/P2 scenarios. Concise findings may share evidence, but omissions cannot be replaced by a general assurance.

| Section | Mandatory substantive content |
| --- | --- |
| `identity` | Task/profile; BASE/HEAD; packet digest/bytes; inventory digest; requested model versus actual native-reported identity and limitations; native terminal status/finish source, with NOT EXPOSED where appropriate; pseudonymous session and independence |
| `scope` | Exact complete changed-file list with revision/blob/SHA256/lines; exact governing C1/C2 authority spans; full candidate inspected, source/transport parity and before-state limitations |
| `coverage` | Every axis below, specific inspected evidence and adversarial scenario; domain N/A requires an explicit scope-based rationale |
| `findings` | Explicit P0, P1 and P2 assessments, even NONE; each finding has stable ID, severity, source path/lines, reproducible failure scenario, impact, suggested correction and evidence limitations; preserve material severity |
| `negative_checks` | Length-ending, missing final report/section/axis, stale HEAD/packet/inventory, absent changed file/span, identity correction, peer contamination, cumulative/cache ambiguity and contradictory success claims |
| `limitations` | Numeric caps UNSUPPORTED/NOT VERIFIED; actual-model/finish/counter/transport limitations; tests observed versus executed; source authenticity and semantic coverage cannot be proved by receipts |
| `conclusion` | COMPLETE / INCOMPLETE / UNKNOWN report state, findings/no findings, unresolved issues and Gate Owner disposition required; native COMPLETE is not Gate PASS |

Required axes: `source_integrity`, `authority`, `correctness`, `security`, `tenant_rbac`, `privacy`, `audit`, `cas_currentness`, `tests`, `review_completeness`, `independence`, `budget_telemetry`. For this offline task, tenant/RBAC, audit mutation and CAS/runtime may be N/A with explicit `NO_RUNTIME_CHANGE` or `OFFLINE_ONLY` rationale and evidence. Still assess provenance/currentness, privacy and fail-closed controls substantively. Other axes cannot be N/A. No missing P1/P2 discussion or reduced material risk coverage is acceptable merely because no finding was discovered.

A finding is a review result, not an incompleteness condition. Developer adjudication labels VALID / INVALID / DUPLICATE / OUT_OF_SCOPE / ADVISORY need evidence under Gate Owner oversight; UNADJUDICATED material findings cannot become acceptance. Fix valid source defects, then freeze a new clean HEAD and renew both reviews and exact-head CI. Final findings can be complete while the candidate remains blocked.

## Attempt state machine and bounded retry

`DISPATCHED → NATIVE_TERMINAL_OBSERVED → FINAL_REPORT_INSPECTED → COMPLETE / INCOMPLETE / UNKNOWN`. All identities, source coverage, axes, severity assessments and independence must be established, in addition to native terminal completion. Unknown evidence is never silently upgraded.

| Evidence | Outcome / action |
| --- | --- |
| `finish=length`, `MAX_TOKENS`, truncated transport/source, native error/safety/tool-only/nonterminal response | INCOMPLETE, even if a success field or earlier attempt claims COMPLETE |
| Completed process/provider but absent substantive final report/section/file/span/axis/P0-P1-P2 discussion | INCOMPLETE |
| Missing native model, terminal receipt, finish evidence or isolation evidence | UNKNOWN unless a separately known failure already makes it INCOMPLETE |
| Gemini finish NOT EXPOSED, independently valid native terminal completed/SUCCESS, complete final report and verified source/model/isolation | May be mechanically COMPLETE; record NOT EXPOSED, never fabricate stop |
| Peer output seen or shared reviewer session | INCOMPLETE; independence repair requires separately approved fresh dispatch |
| Changed BASE/HEAD/packet/authority inventory | Stale evidence; new freeze, new input inventory, both reviews and exact-head CI. Preserve old attempts outside the new candidate's receipt set |

Keep every failed attempt, full sanitized final report if any, native finish/terminal provenance and measured metadata. After any incomplete native attempt, **STOP for Gate Owner bounded retry approval**, including identity correction, transport failure or missing final sections. Do not retry merely because the runner is available, discard failed attempts or repeat 32k reasoning blindly. The synthetic historical retry records model approvals for testing; they do not authorize any live retry.

Classify retry as FINISH_LENGTH, REPORT_INCOMPLETE, MODEL_IDENTITY_CORRECTION, CONTEXT_INSUFFICIENT or TRANSPORT_FAILURE and link the exact predecessor and explicit approval. Revalidate frozen source, byte-identical peer inputs and independence before approved retry. No settings changes are supported by this v1 checker. An actual verified native-safe adjustment would require separately recorded capability/provenance and approval outside this checker; caps remain unsupported here. Renewed source/packet invalidates both reviewers' old reports. No change to provider/account/global settings is permitted by this profile.

## Offline receipt schema v1.0 and limits

[`scripts/valora_reviewer_profile_check.py`](../../scripts/valora_reviewer_profile_check.py) validates **sanitized metadata receipts**, not native transcript/report text or provider authenticity. A reviewed final report is retained separately; receipt digests bind assertions to independently retained evidence. There is no content reading, Git inspection, provider/GitHub/network call, credential/environment lookup or file output in the checker. Native discovery and substantive reviews remain human/process evidence. A matching hash alone proves neither truthful source selection nor independence nor substantive adequacy.

The only input is one explicitly selected regular nonsymlink `.json` file, strict UTF-8, at most 2,000,000 bytes. Duplicate JSON keys, NaN/Infinity, unknown fields, unsupported versions, non-allowlisted labels/paths, case-colliding rows and invalid ranges block the entire input with constant safe codes. No rejected values, filenames or exception messages are echoed. Array boundaries allow at most 1,000 rows; integers exclude booleans and range up to 10^9. Digests are lowercase SHA256 (64 hex) or Git SHA1 identities (40 hex), never claimed as commit authenticity.

The envelope has exactly `schema_version="1.0"`, `profile_version="1.0"`, `sanitized_metadata=true`, `expected`, `attempts`. The checked-in [complete fixture](../../scripts/tests/fixtures/valora_reviewer_profile/complete.json) is the full field/type example; [negative cases](../../scripts/tests/fixtures/valora_reviewer_profile/negative_cases.json) exercise omission and contradiction. All object fields are required; explicit null is allowed only at documented unavailable-evidence fields. Unknown/freeform report, prompt, reasoning, secret and usage-counter fields are rejected. `source`/`approval_ref` permit only SYNTHETIC or a public Valora GitHub Issue/PR comment reference; a reference is never fetched or independently authenticated.

`expected` contains `identity`, `changed_files`, `authorities`. Identity includes task ID, BASE, HEAD, packet SHA256/bytes and #160 manifest's normalized inventory SHA256. Changed-file rows include path, revision (head/base), blob SHA1, source SHA256 and total lines. Authority rows include path, blob/SHA256/lines, C1/C2 tier and ordered nonoverlapping inclusive spans; CODEX and ENGINEERING_GUARDRAILS are required. Other task authority must be chosen independently against the contract. Changed-authority overlap must agree exactly and be at HEAD. This checker cannot discover a missing source or semantically wrong authority in a self-declared expected set. CLI pins BASE/HEAD/packet separately and the SHA256 of canonical reviewed `expected` metadata (sorted changed-file/authority rows, sorted JSON keys, compact separators, ASCII escaping, trailing LF). This receipt-set digest is **distinct** from the manifest inventory and packet digests; recomputing an unreviewed set does not approve it.

Each attempt contains allowlisted ID/provider, monotonic provider attempt number starting at 1, session SHA256, exact identity, requested/native model, native terminal/finish receipts, independence receipts, final-report metadata or null, retry or null, and a #159 telemetry event reference. Telemetry stores only event ID/snapshot kind/adapter/source: counter arithmetic stays in the certified #159 collector, which independently audits the [synthetic usage control](../../scripts/tests/fixtures/valora_reviewer_profile/a19_usage.json). Missing usage is not converted to zero; no measured savings are inferred. A native NOT EXPOSED finish must have no fabricated finish digest; its separate terminal digest is mandatory for completion.

Final-report metadata contains state, full report digest/source, seven section receipts, exact changed-file/authority lists, all twelve coverage rows, all three severity assessments and finding receipts. Every section/axis/severity needs a nonnull evidence digest for completeness. Each finding carries ID, P0/P1/P2, source path/line interval, failure-scenario/evidence digests and disposition. Its lines must belong to a complete changed source or actually supplied authority span. NONE/FINDINGS severity declarations must agree with the finding list. No-finding reports still require all sections/axes/severity evidence. Actual narratives, meaningful source-line evidence and reasonable severity remain independently inspected in the separate final report.

Attempt history is ordered by provider/attempt; unique IDs and exact consecutive numbering are required. Retries must link the previous provider attempt, include an approval reference, classify its observed failure correctly and keep settings unchanged. Missing/invalid historical retry approvals/settings invalidate the receipt set even if a later attempt completes. All attempts in one set use one frozen identity; stale historical identity blocks and belongs in separately retained old evidence. Latest attempt per provider determines completeness: a later incomplete/unknown attempt invalidates an earlier complete result. A later clean flag cannot erase contamination or unknown isolation in the same session. Findings from earlier attempts on the same source must remain identifiable with the same scenario/source interval and no severity downgrade, including rejected findings retained for adjudication. Exactly one current DeepSeek lane and one current Gemini lane, with distinct nonnull session pseudonyms and uncontaminated isolation receipts, are mandatory; missing reviewer/session evidence never lowers review count.

Across different provider lanes, every non-null session SHA256 from any historical or current attempt must be disjoint. Any collision yields `REVIEWER_SESSION_COLLISION`, aggregate INCOMPLETE and CLI exit 1. Same-provider reuse remains governed by the existing history/isolation checks; null identities never establish independence.

Output has `mechanical_preflight=COMPLETE/INCOMPLETE/UNKNOWN`, `gate_authority=NONE`, `evidence_authenticity=SOURCE_ASSERTED_NOT_AUTHENTICATED`, sorted safe codes and every historical attempt's state/finding count. COMPLETE may contain findings requiring adjudication; it is never reviewer quality PASS or Gate acceptance. Exit **0** = mechanically COMPLETE; **1** = valid metadata but INCOMPLETE/UNKNOWN; **2** = malformed/unpinned input, constant error on stderr, UNKNOWN, no partial stdout. Output contains no narrative or source paths. An IO/schema error blocks before any report emission. The CLI writes only stdout/stderr.
