## Authority and product surface

The existing Workbench hosts the project quotation workspace. Only the exact server PENDING `supplier_quotes_prepare_required` / `supplier_quotes_preparation` context opens and focuses it; its deficient sealed line is selected without submitting a quote or selection command. The four Asset Context tabs remain `Tổng quan | Thông số kỹ thuật | Nguồn giá & Chứng cứ | Lịch sử`. PRICE_EVIDENCE retains its separate A11 region and asset tab. Completed upstream regions use existing disclosures while the server identifies the quotation stage.

The [Frontend Architecture Rule](../architecture/VALORA_FRONTEND_ARCHITECTURE_RULE.md) governs presentation: Fluent 2 light primitives, shared fields and existing badges/messages, shared form/dialog/table tokens, feature components/controller, thin Workbench and App composition. The workspace remains table-first and Vietnamese-first. Expanding it gives the quotation table more space while retaining the asset grid. The server's five quotation results, coverage, eligibility, currentness, deficiencies, permitted actions and warnings are displayed directly. React never derives completion, supplier independence, current heads, price differences or warning thresholds.

The typed adapter allowlists the existing six A13 contracts and preserves quantity and price as exact Decimal strings. Supplier, retained source and sealed asset selectors display human labels; UUIDs are carried as values, never typed by users. The issuer selector is explicitly `Nhà cung cấp phát hành báo giá`. Source selection is explicit, uses retained identity and generation, and disables unavailable candidates. Loading additional bounded pages never changes the selected identity. Source metadata contains no object key, storage path, credentials or contact/tax details.

Registration collects the existing quotation terms. Draft line registration supports explicit mapping and editing of an existing mapped line. Correction, replacement and negotiation append the existing revision command, with previous terms and exact mappings visible for deliberate review. Correction can explicitly choose a different active issuer; replacement and negotiation retain the previous issuer. Reasons and any existing concern-resolution evidence use the accepted contract. There is no supplier-creation, ingestion, upload, OCR, parser, remote fetch or content-verification workflow.

`Hoàn tất báo giá NCC này` sends one explicit confirmation against the displayed revision and full current seal/line/session/source/supplier CAS. It opens no professional checklist, second confirmation or approval modal. Server warning codes remain informational and do not hide a server-permitted confirmation. Withdrawal targets the server's confirmed revision, including when another latest draft exists; rejection targets a server-permitted draft. Both require a reason and preserve history. No automatic revision fallback or quote-to-working-price copy occurs.

## Failure, receipt and downstream boundaries

One command UUID and contract are persisted before transport, scoped to tenant/actor/project. Storage failure prevents dispatch. The mutation request bypasses the shared client's automatic 401 replay. Transport failure, 500 or an incoherent receipt retains the original identity and blocks new quotation commands. Explicit recovery requests that historical receipt before refreshing coherent preparation, history and Case State. A receipt never substitutes for current coverage. A missing receipt conservatively retains recovery; this product offers no automatic or unsupported retry.

401/403/404 reads remove protected data. Command authorization failure keeps writes locked. A 409 refreshes authority and does not replay the command; forms bound to old tokens stay disabled. Background failures retain visibly unverified content with writes locked. If integrity prevents history reads with 409, a coherent successful preparation/Case State pair may still display the server's STALE result; history is withheld and writes remain locked. The frontend never repairs source bindings or changes Supplier status to regain eligibility.

Only the existing active owned Workbench session and server `writable`/action flags permit mutations. An intact COMPLETE can remain readable outside DRAFT. A closed owned session returns the accepted safe 404; the product refreshes and disables the form. Viewer reads remain possible, with no write controls. Actual unauthenticated reads clear quotation content and show the session error. Tenant access failures remain safe 404.

COMPLETE displays `NO_AUTHORIZED_DOWNSTREAM_ACTION`. A bounded server-capability presentation guard hides the legacy supplier-selection navigation and prevents its page/service from opening when unavailable. This does not change or activate Supplier Selection authority. No quotation command calls NCC Selection, changes appraised prices, creates AppraisedPriceDecision, changes membership, generates documents, or changes PRICE_EVIDENCE facts.

## Reproduction

Create an isolated Linux backend with the repository's dependencies, the accepted migration head, database name `valora_a14`, real S3-compatible predecessor storage, `DOCUMENT_BLOB_PROVIDER=local`, and pre-provisioned `/var/lib/valora/a14-blobs` outside the checkout. Mount `tests/e2e` at `/e2e`; set a private `A14_SYNTHETIC_PASSWORD`. `bootstrap_g2_a14.py` creates a unique synthetic tenant using `A14_SYNTHETIC_SLUG` and prints its safe fixture JSON. It establishes working-price facts before quotation testing through the existing Human Commit and never writes them from a quotation action.

Run `g2_a14_transport_proxy.py` with `A14_EVIDENCE_DIR`, forwarding local port 8000 to the isolated backend on 8001, and run the existing Vite development server on 5173. Save the primary bootstrap output as `fixture.json`, then run `run_g2_a14_live.py`. That journey archives its synthetic project after confirming the final successor; use a new fixture for a full rerun.

For each of `missing`, `corrupt`, `inactive`, `merged`, `ambiguous`, create a distinct `A14_CONFIRMED_FIXTURE=1` tenant and save `fixture-{fault}.json`; run `run_g2_a14_currentness.py`. These externally injected faults are intentionally irreversible fixture changes, never product actions. For additional negatives, bootstrap a distinct confirmed tenant with `A14_ZERO_WORKING_FIXTURE=1`, save `fixture-negatives.json`, and run `run_g2_a14_negatives.py`. The browser fixture has zero and unassessed working-price cases; the independent exact threshold tests also cover comparable zero, NULL and incomparable bases separately.

The private evidence directory includes fixture JSON, safe transport receipts, server projections and raw test outputs. Password files and retained byte contents are excluded from committed evidence. Nothing here authorizes deployment, Ready, merge, issue closure or certification.
